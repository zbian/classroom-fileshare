## 1 与 M1 的关键差异（先说限制）

| 维度 | M1 | M2（本方案） |
| --- | --- | --- |
| 数据流向 | 教师 → 学员（单向广播） | **双向**：学员 → 教师定向回传（FR-S-02/03） |
| 角色端 | 主要验教师侧 + 单机代理学员 | 必须同时有**教师端 + 多个真实学员端**（回传、分组、删除同步都依赖多学员） |
| 单机可验性 | 大部分可单机 | **可单机 + 多 agent 进程代理**（已批准口径），但「多台真机 UDP 发现/网络中断」类仍延后 |
| 离线语义 | 基本不涉及 | TC-08 的「离线端」、TC-09 的「断网」是核心判据 → 需用**受控手段模拟离线**（§3.4） |
| 教师端视图 | 「我共享的」单列表 | 新增「学生提交」**左侧昵称分组树 + 右侧列表**（FR-T-05 / C2） |

**单机代理的基本形态**（沿用 M1 已批准 §5.2 口径）：
- 1 个**真实教师服务**（`classroom-svc --console`，teacher 模式，独立数据根）；
- N 个**真实学员进程**（真实 agent 代码，不同昵称/数据根，`manual_addr` 指向教师，避免同机 UDP 47820 端口独占冲突）；
- 教师侧操作通过真实 GUI 或真实 IPC 客户端；学员侧操作通过真实 GUI 或真实 agent 进程接口。

## 3 全局验收环境（M2）

### 3.1 机器与拓扑（单机代理为主）

| 角色 | M2 最低 | 说明 |
| --- | --- | --- |
| 教师服务 | 1 个进程 | `classroom-svc --console`（teacher），独立隔离数据根 |
| 学员端 | **≥3 个真实 agent 进程**（TC-05 需 3 人 × 2 条） | 不同 nickname + 不同 data_root，`manual_addr` 指向教师；TC-08 需可**逐个停/起** |
| 教师 GUI | 1 个（真实 GUI） | 用于「学生提交」分组树/删除确认/同步进度取证（UIA + 截图） |
| 双机真机 | 延后 | 真实 UDP 发现、跨机网络中断（拔网线）列入 #91 |

### 3.2 数据根隔离（必须）

- 教师：`<iso>\teacher\ClassShare\data`；学员 i：`<iso>\stu<i>\ClassShare\data`（通过 `LOCALAPPDATA`/`APPDATA` 环境变量隔离，**不要污染本机真实数据根**）。
- 执行前后各记录一次数据根清单，证明隔离生效（M1 做法沿用）。
- 同一台机不并存双角色服务（设计如此）：教师与学员分别用**独立 svc.json + 独立 LOCALAPPDATA** 启动，互不干扰。

### 3.3 时钟与证据

- 时延类（TC-04/05 的「2 秒内」、TC-08 的「10 秒内」、TC-09 的「10 秒内」）：同机多进程**同钟**（直接用 epoch ms 对齐），无需跨机校正；跨机项延后。
- 证据规范沿用 M1：`docs/acceptance/evidence/M2/<TC>/`，UTF-8 无 BOM、路径脱敏 `<repo>`/`<iso>`；截图/UIA 文本/命令输出三选二以上。

### 3.4 离线与断网的受控模拟（M2 关键）

| 场景 | 模拟手段 | 判据与注意 |
| --- | --- | --- |
| TC-08 离线端 | **停掉指定学员 agent 进程**（`Stop-Process`），其余保持在线 | 离线端数据根**保留**（不删），用于上线后核验补删；教师端应显示「N 台离线，上线后自动删除」（PRD 8.3 文案） |
| TC-08 延迟补删 | 重启该 agent（同昵称/同数据根）→ 重连对齐 Manifest | 从重连成功到条目消失 **≤10 s**；同时核验**磁盘实体**消失（不只是列表） |
| TC-09 断网 | 停教师服务（学员端进入不可达）**或**停学员 agent 的教师连接（更贴近断网）→ 学员产生待发操作 → 恢复教师服务 | 优先用「停教师服务」：学员端 `Disconnected` → PendingOp 入库；恢复后 ≤10 s 全部送达 |
| TC-09 幂等 | 恢复过程中**重复触发**同一操作/重连两次 | 教师端条目数不增（event_id 去重 + version 判旧） |

> 注意：`Stop-Process` 是「进程消失」，TCP 会产生 RST；与「合盖休眠/拔网线」的静默断链不同。**静默断链场景**（心跳读超时）在 M2 属 #16 的会话活性治理，若实现未覆盖则如实标注延后。

## 4 分用例方案

### 4.1 TC-04 学生定向回传

**(a) 前置环境**
- 教师服务已启动（room=XK-204）；3 个学员 agent 已加入（stu01/stu02/stu03，各自隔离数据根）。
- 教师 GUI 已打开「学生提交」Tab（C2），记录**基线**：分组树计数（应全 0 或已知值）、右侧列表条数。
- 学员端记录基线：各自「教师共享」与「我共享的」条数、数据根文件数。

**(b) 执行步骤（点击级）**
1. 学员 stu01：右键浮动图标 → 「粘贴并共享」→ 剪贴板放 128 字文本 → 确认框显示**接收对象「仅教师」**（FR-S-02）→ 发送。
2. 观察：教师 GUI「学生提交」中 **stu01 分组计数 +1**，右侧列表出现该文本；**stu02/stu03 端**列表条数、tips、数据根文件数均**不变**（关键判定）。
3. 学员 stu01：资源管理器选中 2 个文件 → 右键「课堂共享」→ 发送；教师端 stu01 分组计数 **+2**，条数与文件大小正确。
4. 学员 stu02：发送 1 个文件；教师端 stu02 计数 +1，stu01/stu03 不受影响。
5. 学员 stu01：删除自己的一条文本（「我共享的」→ 删除）→ 教师端对应分组条数 -1（FR-S-05 的删除同步；与 TC-08 联动）。
6. 反向检查：学员端「教师共享」Tab **无任何学员提交内容**；学员端不提供「学生提交」视图（3.3/3.4）。

**(c) 预期与判定**

| # | 判定项 | 标准 | 来源 |
| --- | --- | --- | --- |
| 1 | 仅教师端该昵称分组可见 | 教师端分组计数与列表正确（+1/+2） | TC-04 主判据 |
| 2 | 其他学员端无变化 | 列表条数、tips 触发次数、数据根文件数**全部不变**（差值 0） | TC-04 主判据 / 3.3 |
| 3 | 接收对象固定「仅教师」 | 确认框显示「仅教师」，无「发给全班」选项 | FR-S-02 |
| 4 | 学员端不可见他人内容 | 「教师共享」无学员条目；无学生-学生可见入口 | 3.3 / 3.4 |
| 5 | 本人删除同步 | 教师端对应条目 2 秒内消失 | FR-S-05 |

**(d) 证据**
- 教师 GUI「学生提交」分组树前后截图 + UIA 文本（含计数）。
- 三个学员端列表前后条数（IPC/UIA）+ 数据根 `Get-ChildItem` 计数。
- tips 触发次数（学员端 tips 窗口可见性轮询，应为 0 次新增）。
- 两端口 svc log 的 `received/applied` 锚点（证明数据实际到达教师、未到其他学员）。

**(e) 单机限制与替代**
- 无硬性限制：单机多 agent 可完整覆盖 TC-04 的数据可见性判据；**跨机真实链路延后**（#91）。
- 「学生 1 步设昵称」的 UI 交互需学员 GUI；可复用 M1 的昵称弹窗验证（若学员 GUI 起不来，用 agent 进程 + 昵称直设，标注交互未验）。

### 4.2 TC-05 按学生分类

**(a) 前置环境**
- 教师服务 + 3 个学员 agent（alice/bob/carol），互不重名（重名拒绝已在 M1 验过）。
- 教师 GUI 打开「学生提交」，分组树基线为 0。

**(b) 执行步骤（点击级）**
1. alice 提交 2 条（1 文本 + 1 文件）；bob 提交 2 条（2 文本）；carol 提交 2 条（1 文本 + 1 文件）。
2. 观察分组树：alice=2、bob=2、carol=2；**总数=6**。
3. 点击 alice → 右侧列表**只显示 alice 的 2 条**；依次点 bob/carol 验证过滤正确。
4. 未读标记：新到达条目高亮；打开/复制后标记已读（计数变化）。
5. 学员端交叉检查：alice 端「我共享的」只有自己 2 条；**看不到 bob/carol 的任何内容**。
6. 边界（FR-T-05 异常）：离线学员 bob 断开后 carol 再提交 → bob 分组计数不变、carol +1；bob 重连后其历史提交**合并进 bob 分组**（不丢、不串组）。

**(c) 预期与判定**

| # | 判定项 | 标准 | 来源 |
| --- | --- | --- | --- |
| 1 | 分组计数正确 | 每人 2、总数 6 | TC-05 主判据 |
| 2 | 切换昵称过滤正确 | 点 X 只显示 X 的条目 | TC-05 主判据 |
| 3 | 学员端互不可见 | 各学员端仅见本人提交 | 3.3 / 3.4 |
| 4 | 未读/已读 | 新到高亮；查看后已读 | FR-T-05 |
| 5 | 离线学员合并 | 重连后历史提交归入其分组 | FR-T-05 异常 |
| 6 | 教师不可代改 | 「学生提交」无编辑/删除按钮 | 3.4 / FR-T-05 |

**(d) 证据**：分组树截图（含每人计数）、三个过滤状态截图/UIA、学员端「我共享的」条数、tip/未读状态截图。

**(e) 单机限制**：无（3 个 agent 进程即可）；真实多机延后。

### 4.3 TC-08 删除同步与延迟补删

**(a) 前置环境**
- 教师服务 + **N 个学员 agent**（N 按可用资源；PRD 用例为 28 台，31.5 见 §5 规模口径）。
- 教师先广播 1 个文件 `删除测试.pdf`（约 1 MB），**确认 N 台全部已落盘**。
- 指定其中 **k 台**（建议 k=2~3，PRD 为 4/28）**停掉 agent 进程**标记为离线。

**(b) 执行步骤（点击级）**
1. 教师 GUI「我共享的」→ 选中该文件 → 点「删除」。
2. 确认弹窗：文案必须为 PRD 8.3「删除后将从所有学员端同步移除本地副本，此操作不可撤销」→ 确认。
3. 观察：**在线端**列表立即消失（记时：从确认到消失 ≤1 s 目标）；离线端不在线，教师端显示同步进度（如「24 / 28 台已删除」或「k 台离线，上线后自动删除」，E4 界面）。
4. 磁盘核验：在线端数据根该文件**实体消失**（`Get-ChildItem` + 索引查询）。
5. 延迟补删：**重启离线学员 agent**（同昵称/同数据根）→ 从重连成功起计时 → 观察该条目在 ≤10 s 内：列表消失、磁盘实体消失、索引 `deleted=1` 或行移除。
6. 幂等：对同一删除事件重复投递/重复重连，不得报错、不得复活条目。

**(c) 预期与判定**

| # | 判定项 | 标准 | 来源 |
| --- | --- | --- | --- |
| 1 | 在线端立即消失 | 列表/磁盘/索引三者同时消失，≤1 s | TC-08 主判据 |
| 2 | 离线端上线补删 | 重连后 **≤10 s** 副本+索引清除、界面不显示 | TC-08 主判据 |
| 3 | 教师端不阻塞 | 离线台数不阻塞删除完成（进度可见） | FR-T-08 |
| 4 | 二次确认文案 | 与 PRD 8.3 逐字一致 | FR-T-08 |
| 5 | 幂等 | 重复 delete 不报错、不复活 | 3.6 / 7.4 |
| 6 | 状态可视 | 「延迟删除/待删除」状态标签 + 色块 | 7.6 状态字典 |

**(d) 证据**：确认弹窗截图；在线端前后列表 + 磁盘清单 + 索引查询；离线端重连时间戳与补删完成时间戳（算 Δ）；教师端同步进度截图；两端口日志 delete 事件行。

**(e) 单机限制**：真实 28 台不适用（§5）；「静默断链」离线（非进程退出）若 M2 未实现心跳超时，标注延后。

### 4.4 TC-09 离线补发

**(a) 前置环境**
- 教师服务 + 1~3 个学员 agent（stu01 为主要被测端）。
- 学员端记录基线：教师端该生分组条数、学员端「我共享的」状态。

**(b) 执行步骤（点击级）**
1. **制造断网**：停教师服务（最贴近「教师机不可达」）→ 学员端应进入 `Disconnected`/「未连接」状态（EX-08）。
2. 学员 stu01：在离线状态下提交 **2 条**（1 文本 + 1 文件）→ 界面状态显示「待发送（2 条）」，队列可见（FR-S-08）。
3. 恢复：重新启动教师服务 → 学员端自动重连。
4. 观察：**≤10 s** 内教师端 stu01 分组出现这 2 条，状态变「已送达/已同步」；学员端队列清空。
5. **无重复**：教师端该生分组条目数 = 基线+2（不是 +4）；索引按 event_id 去重、version 判旧。
6. 幂等强化：在恢复过程中强制再重连一次（重启学员 agent，仍带同队列）→ 教师端仍不产生重复条目。
7. 补发顺序（FR-S-08）：多条待发按**操作时间戳顺序**补发（可在日志中核对 event ts 递增）。

**(c) 预期与判定**

| # | 判定项 | 标准 | 来源 |
| --- | --- | --- | --- |
| 1 | 离线可提交并排队 | 显示「待发送」2 条，不丢 | FR-S-08 |
| 2 | 恢复后全部送达 | **≤10 s**，教师端收到 2 条 | TC-09 主判据 |
| 3 | 无重复条目 | 教师端条目数 = 基线+2；各端无重复 | TC-09 主判据 / 3.6 |
| 4 | 顺序与状态 | 按时间戳顺序；状态「待发送→已送达」 | FR-S-08 / 7.6 |
| 5 | 断开提示 | 「未连接教师机，内容将在恢复后自动发送」（EX-08 文案） | 10 章 |
| 6 | 队列持久化 | 断网期间重启学员 GUI/进程，队列不丢（PRD 9.2） | FR-S-08 / 9.2 |

**(d) 证据**：断网前后学员端状态截图（含「待发送 2 条」）、教师端分组前后截图、重连时间戳与送达时间戳（算 Δ）、`PendingOp`/索引查询、两端口日志（含 event_id 去重行）。

**(e) 单机限制**：用「停教师服务」模拟断网（近似），真实拔网线/跨机延后（#91）；静默断链（无心跳超时）如未实现则标注。

### 4.5 扩展：rename 与占用重试（FR-T-04 / FR-T-07 / TC-07，来自 #19/#20）

- **rename**：教师重命名 → 学员端「教师共享」**2 秒内**更新（含磁盘文件名/索引 rel_path 一致）。
- **占用重试**（TC-07）：用阅读器锁定学员端目标文件 → 教师覆盖同名文件 → 学员端显示「被占用重试」→ 关闭阅读器后**自动完成覆盖**（无需人工），最多 5 次退避；不阻塞其他共享。
- 判定：状态标签+色块正确（7.6）、重试次数≤5、最终内容为最新版且 bak 1 份。

## 5 结果判定与放行口径

### 5.1 单用例判定

## 8 风险与预防

| 风险 | 预防 |
| --- | --- |
| 同机多 agent 争用 UDP 47820 → 发现失败 | 一律用 `manual_addr`，不走自动发现（发现能力已在 M1 E9 验过） |
| 停进程 ≠ 静默断链 | 判据里明确「进程退出型离线」；静默断链（心跳超时）若未实现则标注延后，不冒充通过 |
| 时延测量重演 M1 O-2（锚点语义错位） | 优先用「操作发起时刻→目标端可见」的墙钟差；若用日志锚点，须先核对锚点位置语义并写入报告 |
| 教师/学员数据根互相污染 | 全程隔离 `LOCALAPPDATA`/`APPDATA`/`PROGRAMDATA`，前后各记录一次清单 |
| 多 agent 进程数受资源限制 | 报告写明实际数；TC-08 用「比例离线」而非硬凑 28 台；真机压测留 M3 |

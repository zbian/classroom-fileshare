## 1. 上游修复 ✓（不靠下游兜底）

`file_args` 首行 `.filter(|a| !is_self_exe(a))`——在**发送链路入口**排除自身 exe，不再依赖服务端「高风险类型」拦截。evidence 文档把「防御全靠下游，清单调整/产物改名即会广播程序本体」写入根因，定性准确。

## 2. 两入口覆盖 ✓

启动 `file_args(&startup_args)` 与单实例回调 `file_args(&argv…)` **共用同一函数** → 结构上覆盖两条路径。evidence 实测单实例回调 **`argc=2` / `argv=[exe, 文件]`**——与**插件源码结论一致**：`tauri-plugin-single-instance-2.5.5` `src/lib.rs:41-44` 文档明写「collected by `std::env::args_os`, so the first element is the executable path」，`src/platform_impl/windows.rs:126` 用 `std::env::args_os()` 全量序列化转发。**源码前提获得真机印证** ✓

## 3. `same_path` 回退不误杀 ✓（逐边界分析）

- canonicalize **成功** → 绝对规范化路径精确比较（大小写 / `.` / `..` / 短路径名均由系统归一）
- canonicalize **失败** → 回退「`/`→`\` + `to_lowercase()`」字符串比较 → **只有字符级相同才判自身，不同即保留** ✓ 正是「无法判定时保留」
- 边界推演：① 大小写不同 → canonicalize 或 lowercase 兜住；② 相对路径 → canonicalize 基于 CWD 解析成功则识别为自身，失败则字符串不等 → 保留（且 `is_file()` 也失败 → 被滤，不会误发）；③ `..` 段 → canonicalize 归一；④ 短路径名(8.3) → canonicalize 解析为长名后相等；⑤ 极边缘：路径存在但 canonicalize 失败且恰为自身等价形式 → 理论上可能漏过，但此时 `is_file()` 通常也失败，风险可忽略
- **设计取舍优于建议**：明确不用 `.skip(1)`，理由（插件若将来只传附加参数，`skip(1)` 会吞掉第一个真实文件）正确

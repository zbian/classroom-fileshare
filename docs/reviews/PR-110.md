## 1. net 上行通道设计（接口修订 #11①）——单写任务已核实

- `ClientSessionConfig.outbound: Option<Receiver<Frame>>` + `with_outbound()`；`None` 时 `recv_outbound` 用 `std::future::pending()` **永久挂起** → select 分支休眠，**S1/S2 行为完全不变**
- **单写任务 ✓（评审核实）**：`on_frame(tx)` 与 outbound 分支最终 `send` 到**同一个 `mpsc::Sender<Frame>`**（由唯一 `writer_task` 消费）；select 单任务轮询 → handler 内 send 与 outbound 分支 send 不会并发 → **不存在两条写路径/乱序**
- 通道关闭（调用方 drop sender）→ `outbound = None` 停止监听、会话继续收；会话结束 `drop(outbound)` 让调用方感知
- **8 个 client_runner 既有用例断言零改动 ✓**（diff +40 纯新增，无删除行）

## 2. agent 命令通道

- `AgentCommand{SendText, SendFiles}` + `run_agent_with_commands`；**`run_agent` 保留兼容**（`mpsc::channel(1)` + rx 立即关闭 → 命令泵空转退出，既有 9 用例零改动）
- 事件构造：`owner_id=本机昵称` / `owner_role=Student` / `audience=Teacher` / `event_id=up-{uuid}`；内容经 `FileHeader → CHUNK_SIZE(1MB) Chunk × N → FileEnd`（与教师广播模型对称）
- **预检与教师侧同源 ✓**：文本 `validate_text`（PRD 10.3）、文件 `metadata.len() > MAX_FILE_SIZE`（E10 同源）、`is_risky_ext`（EX-05 同源）→ host 侧权威复检（双层）

## 6. 评审提出的 2 项建议——**均在合并前被采纳**（main `433f6ce` 证据）

1. **批量内存放大 → `stream_command` 流式发送 ✓**：改造为「逐文件：读 → 发 Event+content → `bytes` drop 释放 → 读下一个」，注释「单文件峰值释放后再读下一个（流式语义）」；**逐文件 `MAX_FILE_SIZE` 预检保留** → 消除 N×100MB 峰值，单文件峰值 ≤100MB
2. **会话结束顺序修正 ✓**：
   ```rust
   let _ = notify.send(AgentEvent::Disconnected).await;   // 先通知（svc 状态先变）
   *uplink.lock().unwrap() = None;                        // 再清上行端点
   ```
   注释写明「评审顺序修正：原顺序会在两者之间留窗口——svc 仍认为已连接→对 GUI 返回 Ok，而命令泵已看 uplink=None 丢弃（静默成功）」→ 窗口消除

## 1. 语义变更（按 PRD 7.4 收紧）——裁定：合理

既有用例 `offline_delete_aligned_as_tombstone_on_reconnect` 的断言从「**墓碑保留在本地索引**」（M1 语义）改为「**索引清除 + 实体清理**」：
- **依据成立**：PRD 7.4「补删完成 = 清理实体与**索引**」；旧断言是 M1 占位语义（M1 冻结报告 Deferral 曾记「墓碑保留策略缺失」）
- **性质**：按 PRD **收紧**，非放宽
- **影响面**：仅 agent 本地 store 的补删终态（M2 范围），无 IPC 契约/协议字段变化；旧实现下「墓碑永久留索引」的问题一并解决
- 用例注释已写明「M1 断言过时，改为断言清除；非放宽」

## 2. 两阶段补删与幂等/有界

`align_manifest` 两阶段：① 本地未删 → `soft_delete`（`DeleteDeferred`）② 清实体（失败仅告警，墓碑保留待下次重试）③ **`hard_delete` 清索引**（补删完成）→ 收集上行 Ack。
- **每连接至多一次**：`hard_delete` 后 `store.get` 返回 None → 后续 manifest 比对直接跳过
- **中断恢复**：上次软删后中断（`deleted=1` 但索引未清）→ `local.deleted` 直接进阶段 3
- **重复 delete 幂等**：`soft_delete` 的 `WHERE deleted=0` → NotFound → `info` 日志、不 panic、不重复广播
- **TTL = 7 天**（`TOMBSTONE_TTL_SECS`）：判断合理——PRD 未给数值，7 天覆盖「周末 + 请假」级离线，避免墓碑无限膨胀；**惰性 purge**（只在实际删除时触发，不引常驻定时器）符合低频率删除场景

## 3. 教师删除立即完成（不阻塞）

`delete_item`：soft_delete + 墓碑 + `broadcast_event`，**不等任何离线端**（PRD 7.4）；测试：用例 1（abort agent 后教师删除成功返回）、用例 2（在线端立即收 delete + 重复幂等）✓

## 4. Ack 身份（不绕过 S3 安全面）

`EventKind::Ack` 分支**先于**内容校验；校验 ① 会话已注册（`conns`）② `acked_by == 会话昵称`。设计合理：Ack 的 `item` 是教师条目快照（owner=teacher，学员非所有者），S3 的 `owner_id==昵称` 不适用；且 **Ack 不落库、不改状态**（仅 `HostEvent::DeleteAcked` 上报供 svc 观测，墓碑清理按 TTL 不依赖 ack）→ 无安全面扩大 ✓

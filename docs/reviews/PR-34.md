## 3. lead 点名专项

### 3.1 学员无他人内容（PRD 3.3 第 3 条「不接收其他学生的任何内容」、第 4 条「不得将某学生的提交转发给其他学生」）→ **不符，发现 1 阻塞**

- **agent 侧结构合规**：无发送路径、无订阅机制，仅接收 host 推送 ✓
- **host 侧重推路径失守**：`on_manifest_req`（本 PR 在 t5「仅回清单」基础上新增**内容重推**）使用 `ListFilter { include_deleted: true, ..Default::default() }`——`owner=None`、`audience=None`，列出教师 store **全部**条目（含学员经 `on_event` 入店的提交）并逐条 Event+文件帧重推给请求清单的学员
- **现状可达性**：M1 官方 agent 只收不发，教师 store 实际只含教师条目 → **官方链路行为正确**；但 net 会话允许任意客户端（甚至未 join）发 `Frame::Event`，且 `hub.on_event` 无身份/audience 校验（t5 遗留，非本 PR 引入）——定制客户端可把学员条目写入教师店（更尖锐变体：伪造 `owner_id="teacher"` + `audience=All` 可顶替教师作用域内容），重推即扩散全班。防御目前只靠「官方客户端不发」，不靠代码
- **M2 必然高危**：FR-S-03 回传启用后教师店将真实含学员条目，此路径不修则 3.3 第 3/4 条直接失守。趁本 PR 正在改此函数，现在修最合适
- **修复建议**：filter 加 `owner: Some(TEACHER_OWNER), audience: Some(Audience::All)` + 回归测试（学员事件入店后，重推清单与内容不含学员条目）；建议顺手在 `hub.on_event` 对 `owner != TEACHER_OWNER` 的事件直接忽略（M1 最小加固；M2 的会话身份绑定需 SessionHandler 接口扩展，另走修订流程，不在本 PR 强求）

### 3.2 删除落地（前任在案「同版本 delete 被吞」缺陷的修复质量）→ **修复质量良好 ✓**

缺陷回顾：原 `merge` 对 `Equal` 一律 `IgnoreDuplicate`，而教师删除不加 version → 删除事件与本地同版本时被当重放吞掉，删除永远无法在学员端落地（PR-28 评审复评段检查点 2 在案）。修复链条四层验证：

1. **协议层**：#5① 语义修正 + 2 红绿测试（含「已删重放仍幂等忽略」的反向边界）✓
2. **索引层**：`soft_delete` 不动 version（墓碑与清单比对自洽）；`apply_remote` 去重→合并→同作用域让位→落索引完好；教师重发同条目 version=2 时 Greater→Overwrite 可复活条目，语义自洽 ✓
3. **在线路径**：端到端 `delete_removes_index_and_body`——删除事件 → 墓碑在索引、默认列表不可见、实体文件已清、`Removed` 通知携带正确 id ✓
4. **离线补删**：`align_manifest` 对清单中 `deleted=true` 且本地未删的条目落地墓碑 + 清实体（本地已删/不存在幂等跳过）——覆盖「学员离线期间教师删除」场景 ✓（无直接测试用例，见发现 4）

## 4. 发现问题

### 发现 1（阻塞——request changes 依据）：清单重推未按 owner/audience 收敛（PRD 3.3 第 3/4 条）
见 §3.1。修复面：hub.rs `on_manifest_req` 一行过滤 + 一个回归测试（建议连同 `on_event` 最小加固与发现 4 的用例一并提交）。

### 发现 2（重要观察，转 lead 裁定归属，不阻塞本 PR）：DupNickname 判致命 + 教师侧半开连接滞留 → 学员被锁出
`join_rejection_is_fatal` 对 DupNickname 一视同仁地致命退出；而教师 conn 表仅在 `on_disconnect`（读帧结束）时移除——学员机器休眠/断网（无 RST/FIN，教师读无超时）期间旧昵称滞留，学员唤醒重连即收 DupNickname → agent 直接退出，学生被锁出直至教师重启。官方 GUI（T-10）集成前需定夺：教师侧 Hello 重名驱逐旧会话，或 agent 对 DupNickname 退避重试。EX-02 的「重名拒绝」语义本身实现正确，本项是重连场景的可用性缺口。

### 发现 3（轻微，记录备查）
- `ServerHandle::shutdown` 用 `notify_waiters`（无存储语义）：accept 分支处理与下一轮 select 注册之间的微小窗口丢通知 → 停机失效；`run_host` 1s 超时兜底使后果良性（进程退出）。建议改 `notify_one`（许可可存储，单一 waiter 场景严格更优）或循环头查 AtomicBool
- `Server.sessions` Vec 仅停机时 drain，长期运行中已结束的 JoinHandle 累积（课堂规模无碍）
- 退避值不在成功会话后重置（长会话断开后固定 5s 重连，轻微）
- 心跳仅写向 Ping、无 Pong 读超时：教师静默死亡（断电）感知依赖 TCP 栈，分钟级。M1 可接受，M2 建议加读超时

### 发现 4（轻微，建议随发现 1 一并处理）：align_manifest 无直接测试
离线补删是 PRD 7.4 状态机的关键分支，建议补「教师删 → 学员离线 → 重连 → 墓碑对齐 + 实体清理」用例。

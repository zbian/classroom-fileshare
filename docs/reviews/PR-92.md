## 1. 未 join 守卫（设计 §3.2）✓ 五类帧全覆盖

`Event` / `FileHeader` / `FileChunk` / `FileEnd` / `ManifestReq` 五处均判 `joined_session`，未 join 时 `warn` + `continue`（**不回帧、不断连**——避免被探测）。

测试真实验证两件事：
- net `frames_before_join_are_dropped`：未 join 注入**五类帧** → handler **零回调**（MockHandler 计数断言）；**对照组** join 后同一事件正常分发（证明守卫只拦未认证路径）
- host `unjoined_event_is_dropped`：裸 TCP 发 Event → 不入店/不通知，且 **Ping 仍得 Pong（证明连接未被断开）**

额外收紧（超出设计要求，合理）：已认证后**重复 Hello 拒绝**（设计 §3.2 原为「维持现行为/记 warn」）——已认证会话不得变更身份。

## 2. host 校验顺序与短路 ✓（实现为四重，比设计多一层）

① 会话存在（`conns.get(session_id)`）→ ② `owner_id == conn.nickname`（冒名）→ ③ `audience == Audience::Teacher`（越权广播）→ ④ `owner_role == Role::Student`（角色一致）。每步失败 `warn` + `return`，**不落库/不广播/不 ack**。`on_file_chunk_stream` / `on_manifest_req` 亦补 conns 身份源校验（net 守卫之上再兜一层，双层防御）。

## 3. `owner_role` 校验拒绝 vs 设计「强制 Student」——判定：**更严格、无兼容风险、支持**

- **更安全**：静默改写会掩盖客户端 bug/恶意行为；校验拒绝把违规暴露出来（warn 含 session_id/role/event_id）
- **无兼容风险**：M1 无学员发送路径（S4 才启用），官方客户端不会发学员事件；S4 实现时自然构造正确 `owner_role`
- 建议：设计 §3.3「强制 Student」措辞可精确为「**校验为 Student，不符即拒**」——属文档措辞待修，非实现问题

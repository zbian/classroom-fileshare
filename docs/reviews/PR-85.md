## 1. 发现 0（阻塞 · P0）：分支基点陈旧 → 门禁取证对当前 main 无效

**机制更正（2026-11-17，本记录首版曾误判）**：首版以 `git diff origin/main..bea48f2`（**two-dot 树面**）为依据写成「合并会回退 #86/#87/#88」。经 lead 实测纠正：**squash merge 应用的是 three-dot 差集**（`git diff $(git merge-base) head`），stale base 本身**不会回退 main**。实测对照：

| 判据 | 命令 | 结果 |
| --- | --- | --- |
| **真实合并面（three-dot）** | `git diff origin/main...bea48f2 --stat` | **8 files, 1191 insertions(+), 0 deletions**——纯新增 `docs/acceptance/local-ci.md` + `evidence/M1/local-ci/*` → **本次无回退风险** |
| 树面（two-dot，首版误用） | `git diff origin/main..bea48f2 --stat` | 44 files, 1467+/1679-（含「删除 #86/#87/#88」的假象） |

方法已固化进 [checklist-v1 附录 B](checklist-v1.md#附录-b-分支基点与合并面判据三步法2026-11-17-增补)（三步判据 + 两个方向的错误判例）。

**事实**：PR head = `bea48f2`，`git merge-base origin/main origin/qa/local-ci` = **`1fea3d1`**（rc.3）；远端未 rebase。

**阻塞理由（硬）——证据失效**：门禁取证跑的是 **rc.3 树（127 passed）**，而当前 main 为 **141 passed**（含 #86 E12 +6、#88 S1/S2 +8）→ **该证据不构成对当前 main 的合格证明**（「取证环境 ≠ 发布环境」，与本项目反复出现的「测试形态 ≠ 真实形态」同型）。其次要理由：rebase 后 diff 收敛便于评审，并使「分支对 main 已存在文件的修改/删除」这类叠加风险显形（本次 three-dot 为纯新增，无此风险）。

**修复**：`git rebase origin/main`（`75d0d7c`）→ 重跑 `local-ci.ps1` 留 141 证据 → `git push --force-with-lease`；rebase 后 three-dot 应只剩 `docs/acceptance/local-ci.md` + `evidence/M1/local-ci/*`。

**流程观察**：这是本项目第 7 次「分支基点陈旧」（PR-35/50/53/59/66/86 之后）。**GitHub `mergeable: CLEAN` 只表示无文本冲突，不检测基点陈旧，也不检测内容回退**——合并前应按 checklist 附录 B 三步人工核对。

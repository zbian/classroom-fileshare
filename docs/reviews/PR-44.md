## 4. 发现问题（均非阻塞）

### 发现 1（一般）：SCM Stop 使用 `notify_waiters`——PR-34 C 项同型丢通知窗口
控制回调 `notify_waiters()` 仅唤醒已注册等待者；StartPending 即接受 STOP，若 Stop 在 `run_core` 首次 poll `notified()` 前到达（启动窗口：SQLite 打开/清扫/桥组建，数十至数百毫秒），通知丢失 → 服务永不退出 → SCM wait_hint 超时后强杀（SQLite 抗强杀，无数据损坏，但停机挂起）。建议改 `notify_one`（单许可存储语义，一词修复，与 net 侧 #38 C 项对齐）；可随包或 M2。

### 发现 2（一般）：配置读取失败回退默认 Teacher 配置
`bootstrap` 对 svc.json 加载失败回退 `SvcConfig::default()`（mode=Teacher, room=XK-204）——**损坏的学员机配置会让该机静默变为主机**：广播 beacon 使全班发现列表出现幽灵房间「XK-204」（学员机防火墙未开 TCP 47821 入站，E1 缓解使幽灵房间不可加入，但发现可见性已造成混乱）。建议 fail-fast：报错后 Stopped（SCM 按策略重启→崩溃循环直至人工修复，与 student 核心致命错误「驻留等待」哲学一致需择一）。

### 发现 3（一般，**登记 T-10 检查点**）：事件桥丢弃 `AgentEvent::Disconnected`
`map_notify` 的 `_ =>` 分支吞掉 Disconnected——教师机离线（断电/网络中断）时 GUI 无从感知，「教师机离线→只读缓存模式」（EX-08，M1 agent 组 checklist 项）的信号通路在 svc 桥断裂；Host 核心异常退出同样不可见（GUI 仅在发送时得到「教师核心不可用」）。处置：随本 PR 一行映射 `StatusChanged("与教师机断开，进入只读缓存")`，**或**显式转 T-10 检查点（T-10 紧随合并序列，EX-08 M1 闭环依赖此信号，届时必须闭合）——本评审按后者登记，若 lead 选择随包修请通知复评该行。

### 发现 4（轻微）：取证 #3 日志行示例与实现不一致
issue #14 回写的行格式示例含 `classroom_svc::runtime:` target，实现 `.with_target(false)` 已抑制——qa 解析契约应以实际输出为准，建议修正回写文本（或改回启用 target，二选一）。

### 发现 5（轻微）：双 Store 连接无 busy_timeout
handler store 与核心 store（host/agent 各自打开）并发访问同一 SQLite；未设 `busy_timeout`/WAL，写争用窗口内 handler 读可能瞬时报错（读多写少、查询短，概率低）。建议 `Store::open` 加 busy_timeout pragma（对 #14 升级路径同样有益）。

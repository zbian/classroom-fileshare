## 1. E7 背景与本修复对照

qa 实证（§3.9.1 真实服务二进制 + code=87 服务日志）：原 `icacls <path> /inheritance:r "<user>:(R,W)"` **缺 `/grant`** → 调用整体失败 → ACL 从未生效；叠加 PROGRAMDATA 继承 `BUILTIN\Users:(RX)` 与管道无显式 DACL → 本地非管理员可读令牌即获 IPC 同等权限。评审方独立核对 `token.rs:34-38` 源码确认（PR-35 §2），并修正 PR-38 评审时「仅核意图未核语法」的 ACL 判定口径。

## 2. 派单要点逐项核验

**第二层根因（raw_arg）**：dev 探针论证 std 的 `arg()` 对含特殊字符参数的引号包装会被 icacls 老式解析拒绝（code=87 的第二层成因，隐藏在「缺 /grant」假象之下）——修复以 `CommandExt::raw_arg` 整段原始命令行（路径手工加引号）彻底消除引号歧义。该层论证评审方未独立复现 icacls 行为，但 raw_arg 消歧义在任何一层成因下均正确 ✓（`CommandExt::raw_arg` stable ≥1.62，工具链 1.100）。

## 3. 发现问题

### 发现 0（机制必做）：分支基点早于 E6 合并，squash 将回退 E6
分支基于 `3d07863`（E6 合并 `3603f23` 之前）——diff 显示本 PR 会**删除 E6 的 size 修复与其断言**（与 PR-35 同型问题）。**必须 rebase 到 main @ 3603f23** 后推送，评审方按「diff 仅含 token.rs/测试」免侧重复跑放行。

### 发现 1（重要，安全补全）：存量令牌路径未覆盖 ACL
`load_or_create_token` 的「已存在即读」分支（token.rs:14-19）跳过限权——E7 时代创建的令牌在升级到修复版后**仍带默认 ACL**，存量部署的暴露面持续存在。建议：已存在分支同样执行 `restrict_acl_to_current_user(&path)?`（icacls 幂等、约 50ms；fail closed 语义对存量同样成立）。

### 发现 2（重要，检查点登记——T-9 接线前必须解决）：服务模式 GUI 令牌分发机制缺位
服务以 LocalSystem 运行 → `whoami` 返回 LocalSystem SID → ACL 后令牌文件**仅 LocalSystem 可读**；而用户会话 GUI 需要令牌完成握手——文件读取路径已不可用（修复前靠 world-readable「侥幸可用」；管理员身份启动 GUI 同样不可读，继承已移除）。降级 `--console` 模式不受影响（svc 与 GUI 同用户）。**须 Lead 定分发机制**（选项：授权交互用户 ACL / svc 写每用户副本 / 握手代理等），否则 T-9/T-10 的 TC-11/12 集成会卡在此。注：此为 E7 修复暴露的前置设计缺口，非本 PR 引入。

### 发现 3（轻微）：`sid_parse_rejects_garbage` 测试名与断言不符
实际仅断言 happy path 返回 `S-1-` 前缀，未喂垃圾输入。建议改名（如 `current_sid_parses_with_s1_prefix`）或补垃圾输入负例。

## 1. 虚拟滚动真实性 ✓ 代码级确认（不只看数字）

`VirtualList.tsx`：
- `start = max(0, floor(scrollTop/rowHeight) - overscan)`、`end = min(len, ceil((scrollTop+max(viewportHeight,rowHeight))/rowHeight) + overscan)`、`items.slice(start,end)`——**真的只渲染可视区 + overscan**
- 占位高度 `items.length * rowHeight`（滚动条比例正确）；`translateY(start*rowHeight)` 定位；`ResizeObserver` 同步视口高度；列表变短时按 `maxTop` 回收 `scrollTop`；零依赖

**`rowHeight` 与 CSS 行高严格一致（虚拟滚动经典坑已避开）**：`ROW_HEIGHT = 40`，且在 Row 上**内联 `height: ROW_HEIGHT`** + `box-sizing: border-box` → 实际行高恒为 40px。

**CDP 数字完全自洽（评审方反算验证）**：视口 377、行高 40 → 滚到底 `max = 500×40−377 = 19623` ✓ 与断言一致；顶部 `ceil(377/40)+8 = 18` ✓；中部 `10+16 = 26` ✓；`rowBottom 615 ≤ viewportBottom 616` 最后一行完整可见 ✓

## 2. `.app-content` flex 修复真因判断准确 ✓

原 `.app-content { overflow: auto }` 是普通块 → `.vlist-viewport` 的 `flex: 1` 失效（父非 flex）→ 视口被内容撑高 → 500 条全渲染；修复为 `display:flex; flex-direction:column; flex:1` + **`min-height:0`**（flex 子项可收缩的必要条件）+ `overflow:hidden`，视口侧 `flex:1; min-height:0; overflow-y:auto`。真因与修复均正确。
